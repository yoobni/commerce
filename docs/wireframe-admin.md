# 와이어프레임 — 어드민 (apps/admin)

> 작성: Iseria (planner)
> 최종 수정: 2026-04-28
> 상태: 1차 확정 — 디자인(Vivian) / 프론트엔드(Yuna) 즉시 착수 가능 수준
> 프레임: **Desktop-first 1440×900** (관리자는 PC 전제), 1024 fallback. 모바일은 보조(긴급 주문 확인 수준).
> 관련: `docs/service-requirements.md`, `docs/payment-shipping-policy.md`, `docs/shipping-tracking-plan.md`, `docs/analytics-kpi-event-schema.md`, `docs/wireframe-commerce.md`

## 1. 목표

운영자가 **하루 1회 30분 이내**로 핵심 운영(주문 확인 → 결제완료 처리 → 송장 입력 → 회원/CS 대응)을 끝낼 수 있는 어드민 6개 화면(대시보드 / 상품관리 / 주문관리 / 회원관리 / 정산 / 통계)의 **레이아웃·영역·상태·이벤트 매핑**을 와이어 단위로 확정한다.

이 문서를 보고 디자이너는 시안을, 프론트엔드는 컴포넌트 트리/라우팅/상태 설계를 바로 시작할 수 있어야 한다.

설계 원칙:

- **운영 효율 우선** — 한 화면당 핵심 액션 ≤3, 클릭 ≤2회로 끝나야 한다.
- **고밀도 표 + 사이드 디테일** — 커머스가 spacious라면 어드민은 dense. 표는 sticky header, 우측 슬라이드 패널로 디테일.
- **수동 와꾸 보장** — `payment-shipping-policy.md`의 MOCK 어댑터 정책에 따라, **PG/배송사 외부 연동 없이도 어드민 수동 액션만으로 주문 한 건이 끝까지 굴러간다**.
- **권한 분리 명시** — `super_admin` / `operator` / `cs` / `viewer` 4단계. 각 화면 액션 옆에 권한 표기.
- **빈 상태/로딩/에러/성공 4가지 상태**가 모든 화면에 존재해야 미완료 아님.
- **대량 처리 가능** — 주문/회원/상품 모두 다중선택 → 일괄 액션 지원.

## 2. 포함 범위

- 6개 화면의 와이어(영역, ASCII 다이어그램, 컴포넌트 매핑)
- 화면별 라우팅, 진입/이탈 흐름
- 화면별 상태(로딩/빈/에러/성공) 매핑
- 화면별 운영 이벤트 매핑(`analytics-kpi-event-schema.md` 3장 — 어드민 이벤트는 2차 확장이지만 본 문서에서 1차 후보 정의)
- 권한 매트릭스
- 데스크톱(주) / 태블릿(보조) 차이 명시
- MVP 범위 / 이후 단계 분리

## 3. 제외 범위

- 시각 디자인 결정(`design-system-direction.md` 단일 출처 — 어드민도 동일 토큰 적용, 단 밀도/색조만 운영 톤으로)
- 커머스 화면 와이어(`docs/wireframe-commerce.md`)
- 기존 구현 화면 중 **본 6개에 포함되지 않는** 쿠폰 / 리뷰 / 커뮤니티 모더레이션 / 카테고리 — 흐름 연결만 명시, 화면 와이어는 차기 단계
- 실제 코드 구현(NEED_HELP:developer로 위임)
- 멀티 테넌트 / 멀티 셀러 운영(현 단계 단일 셀러)

```
[Routes]
  /                              대시보드
  /products                      상품 목록
  /products/new                  상품 등록
  /products/[id]                 상품 수정
```

## 5. 권한 매트릭스 (RBAC)

| 역할             | 대시보드 | 상품 R/W   | 주문 R/W      | 배송 R/W | 회원 R/W       | 정산 R       | 통계 R | 설정 |
| ---------------- | -------- | ---------- | ------------- | -------- | -------------- | ------------ | ------ | ---- |
| `super_admin`    | ✓        | ✓ / ✓      | ✓ / ✓ (환불)  | ✓ / ✓    | ✓ / ✓ (탈퇴)   | ✓            | ✓      | ✓    |
| `operator`       | ✓        | ✓ / ✓      | ✓ / ✓ (제한)  | ✓ / ✓    | ✓ / ✗          | ✓            | ✓      | ✗    |
| `cs`             | ✓ (요약) | ✓ / ✗      | ✓ / ✓ (메모)  | ✓ / ✗    | ✓ / ✓ (포인트) | ✗            | ✗      | ✗    |
| `viewer`         | ✓ (요약) | ✓ / ✗      | ✓ / ✗         | ✓ / ✗    | ✓ / ✗          | ✓            | ✓      | ✗    |

> 본 와이어에서 액션 옆에 `[op]`, `[cs]`, `[admin]` 표기. 서버 가드도 동일 키로 매핑(`shared/auth/admin-rbac.ts` 가정).

## 6. 공통 레이아웃

### 6.1 헤더 (60px)

```
┌────────────────────────────────────────────────────────────────────────────┐
│ [logo Muzzle Admin] [env: staging ▼]   [🔍 검색...]   [🔔 N]  [본인 ▼]    │
└────────────────────────────────────────────────────────────────────────────┘
```

- env 토글: `staging` / `prod` (super_admin만 변경).
- 검색: 주문번호 / 이메일 / 상품명 / 회원ID 통합 검색 → 결과 패널 드롭다운.
- 알림: `정산 마감 임박`, `재고 0`, `리뷰 신고`, `대량 환불 요청` 등 시스템 알림.
- 본인 메뉴: 비밀번호 변경 / 운영자 세션 / 로그아웃.

### 6.2 사이드바 (240px, 접기 가능 → 64px)

```
┌──────────────────┐
```

- 빨간 점 배지: 미처리 카운트(서버 액션 1회/3분 폴링 또는 SSE).
- 접힌 상태에서는 아이콘 + tooltip만.
- 권한에 따라 메뉴 항목 자체가 사라짐(즉시 가드).

### 6.3 컨테이너

- 본문: `max-width: 1440px`, padding `24px`, 12 column grid `gap: 24px`.
- 표: sticky header, sticky 우측 액션 컬럼, hover 시 행 배경 변경.
- 우측 슬라이드 패널: 480px(상세) / 640px(편집) — esc 닫기, URL은 `?detail=ID` 동기화.

### 8.5 컴포넌트 / 데이터

- 다국어 입력: `<I18nField>` (탭 ko/en/ja/de, 미입력 시 ko fallback 표시).
- 옵션 변형 표: `<VariantMatrix>` — 옵션축 변경 시 행 자동 재생성, 가격/재고 인라인 수정.
- 이미지: `<MediaUploader>` — Supabase Storage 직접 업로드, presigned URL.
- 카테고리: `<CategoryTreePicker>` — 다중 부모 허용 X, 단일 경로.

`analytics-kpi-event-schema.md`의 KPI를 운영자가 **별도 BI 툴 없이** 어드민에서 바로 확인할 수 있게 한다. MVP는 5개 KPI + 2개 퍼널 + 1개 코호트.

### 12.3 KPI 정의 (MVP 6)

| KPI         | 정의                                                       | 출처                  |
| ----------- | ---------------------------------------------------------- | --------------------- |
| 방문자      | unique anonymous_id (event=`page_view`)                    | events table          |
| 가입        | `signup` 이벤트                                            | events                |
| 첫구매      | user_type=`first_purchase` 인 `purchase` 이벤트            | events                |
| 재구매율    | 30일 내 2번째 `purchase` / 첫구매 회원 수                  | events + orders       |
| AOV         | sum(net) / orders_count                                    | orders                |
| 매출        | sum(net) (정산 화면과 동일 정의)                           | orders                |

### 12.4 퍼널 정의

view_item → add_to_cart → begin_checkout → add_payment_info → purchase. 각 단계 절대수치 + 직전 대비 전환율 + 누적 전환율.

### 12.5 데이터 소스 / 처리

- 이벤트는 `analytics-kpi-event-schema.md` 기반으로 `events` 테이블 적재(MVP는 Supabase 자체, 추후 외부 SDK 가능).
- 통계 화면은 RPC 또는 materialized view로 사전 집계(쿼리 비용 보호).
- 30일 초과 분석 시 "집계 갱신 중..." 로딩 → 완료 후 캐시.

### 12.6 상태값

| 상태             | UI                                                |
| ---------------- | ------------------------------------------------- |
| 데이터 없음      | "이 기간에 이벤트가 없습니다"                     |
| 집계 진행 중     | 카드별 스켈레톤 + "집계 중..." 표시               |
| 데이터 신뢰도 낮음 | 표본 < 100 → 회색 경고 "표본이 작아 변동성 큼"  |
| 비교 기간 변경   | 직전 기간 자동 비교(점선 표시)                    |

### 12.7 이벤트

| event                        | properties             |
| ---------------------------- | ---------------------- |
| `admin_analytics_view`       | tab, filter            |
| `admin_analytics_export`     | tab, format            |

## 16. 리스크

1. **MOCK 어댑터 한계** — 실 PG/배송사 붙기 전에 운영자가 "수동 결제완료"를 잘못 누르면 회복 어려움. → 활동 로그에서 30일 이내 되돌리기 액션 필수.
2. **단일 셀러 가정** — 정산 화면이 멀티 셀러로 확장되면 재설계 필요. 현재 컬럼/스키마는 셀러 추가 가능성을 비워둠 (`orders.seller_id` 추가만 하면 확장).
3. **이벤트 적재 비용** — 통계 화면이 events 직접 쿼리하면 비용 폭증. **반드시 materialized view + 일배치** (NEED_HELP:developer).
4. **PII 접근 로그 누락** — 회원 상세에서 마스킹/원본 토글이 강제 로그 미작동 시 컴플라이언스 위반. 감사 테스트 필수.
5. **권한 가드 누락** — 클라이언트 메뉴 숨김만으로는 안 됨. 모든 RPC/API에 서버 가드 필수, 화면별 RBAC 매트릭스가 단일 출처여야 함.
6. **주문/배송 상태머신 동기 깨짐** — 어드민 직접 상태 변경과 결제 완료 → 자동 상태 변경의 경합. 상태 전이 화이트리스트(`payment-shipping-policy.md` 4.3) 강제 검증.
7. **다국어 입력 빈칸** — 상품 등록에서 ko만 채우고 노출 시 en/ja/de 빈칸 → 커머스에서 깨짐. ko 폴백 명시 + 노출 ON 직전 경고.
8. **다중 통화 정산** — 환율 정책 미확정 → 합산 강제 X 정책으로 1차 회피, 2차에서 환율 테이블 + 일별 fix.
9. **대시보드 알림 폴링 비용** — 3분 폴링 N개 카운트 RPC가 운영자 늘면 비용 증가. SSE 전환 옵션 보유.
10. **어드민 모바일 미지원** — 출장 중 긴급 환불 요청 시 모바일에서 안 됨. 차기 단계 mobile-lite 검토.
